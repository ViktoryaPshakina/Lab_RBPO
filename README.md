# Лабораторная работа №5: Система аутентификации на основе JWT Access и Refresh токенов

## 📝 Описание
Проект представляет собой RESTful API для ветеринарной клиники, в который интегрирована современная система безопасности на базе **Spring Security 6** и **JWT**. В ходе работы реализован механизм разделения токенов на Access и Refresh, а также внедрена защита от повторного использования токенов (Reuse Detection) с хранением сессий в базе данных.

## 🛠 Стек технологий
* **Java 17 / 21**
* **Spring Boot 3.2.0**
* **Spring Security 6** (Stateless)
* **PostgreSQL** (Основная БД)
* **Spring Data JPA** (Hibernate)
* **JJWT (0.11.5)** — для работы с токенами
* **Lombok** — для сокращения шаблонного кода
* **Postman** — для тестирования API

---

## 🚀 Основные возможности

### 1. Безопасность (JWT)
* **Access Token:** Короткоживущий (15 мин), используется для авторизации запросов. Содержит роли пользователя.
* **Refresh Token:** Долгоживущий (7 дней), используется только для получения новой пары токенов.
* **Reuse Detection:** Если скомпрометированный (уже использованный) Refresh-токен попадает к злоумышленнику и он пытается его применить, система автоматически аннулирует (`REVOKED`) всю цепочку сессий данного пользователя.

### 2. Управление данными (CRUD)
Полный цикл операций (Создание, Чтение, Обновление, Удаление) реализован для 5 ключевых сущностей:
* `Owners` (Владельцы)
* `Pets` (Питомцы)
* `Vets` (Врачи)
* `Appointments` (Приемы)
* `Treatments` (Лечение)

### 3. Специальные бизнес-операции
1. **Регистрация владельца вместе с питомцем:** Создание обеих записей в одной транзакции.
2. **История болезни питомца:** Получение всех приемов и назначений для конкретного животного.
3. **Расписание врача:** Список всех приемов конкретного специалиста.
4. **Каскадное удаление владельца:** При удалении владельца автоматически удаляются все связанные с ним питомцы.
5. **Отчет по активным операциям:** Список актуальных приемов в клинике.
