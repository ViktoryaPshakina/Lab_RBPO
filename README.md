# Ветеринарная клиника — Лабораторная работа №4

## Тема: Безопасность API и реализация бизнес-логики

Данный проект представляет собой RESTful API для управления ветеринарной клиникой, защищенный с помощью Spring Security и реализующий сложные транзакционные операции.

## 🛠 Реализованные требования по безопасности

1. **Spring Security**: Полная интеграция модуля безопасности для защиты персональных данных клиентов и медицинских записей.
2. **Аутентификация**: Реализована через **Basic Auth**. Все эндпоинты (кроме регистрации) закрыты и требуют передачи учетных данных.
3. **Ролевая модель (RBAC)**:
    - **ROLE_ADMIN**: Имеет полный доступ ко всем ресурсам клиники, включая управление персоналом (ветеринарами) и всеми записями владельцев.
    - **ROLE_USER**: Доступ к функциям «Личного кабинета». Может просматривать только своих животных и историю их лечения.
4. **Процедура регистрации**:
    - Добавлен публичный эндпоинт `/api/auth/register`.
    - Реализовано хеширование паролей при записи в БД с использованием **BCryptPasswordEncoder**.
    - Автоматическое назначение роли `ROLE_USER` новым пользователям.
5. **Валидация и защита**:
    - **Надежность пароля**: Внедрена проверка пароля при регистрации (минимальная длина 8 символов, обязательное наличие цифр, заглавных букв и специальных символов).
    - **Контроль владения (Data Ownership)**: Пользователь не имеет доступа к данным других владельцев. Реализована логика сопоставления системного логина (`Principal`) с полем `email` в профиле владельца. Попытка доступа к чужим записям возвращает **403 Forbidden**.
    - **Stateless API**: Настроена политика сессий `STATELESS`, исключающая хранение состояния на сервере.

## 💼 Бизнес-операции

В проекте реализованы 5 ключевых бизнес-процессов:
1. **Транзакционная регистрация «Владелец + Питомец»**: Создание профиля владельца и привязка его первого животного в рамках одного запроса (`POST /api/owners/register-with-pet`).
2. **Медицинская карта (История болезни)**: Сбор и вывод всех диагнозов, назначений и лекарств для конкретного животного по его ID.
3. **Расписание ветеринара**: Формирование списка всех приемов, закрепленных за конкретным врачом.
4. **Каскадное удаление данных**: При удалении владельца система автоматически удаляет все связанные записи (питомцев, записи на приемы, историю лечения), предотвращая появление «мусора» в БД.
5. **Аналитический отчет**: Выгрузка списка активных визитов (со статусом `SCHEDULED` или `IN_PROGRESS`) на текущую дату.
